# Blue Eye 遥测数据接口查看器

这是 `blue-eye` 项目的本地 PC 端 USART1 遥测查看器。它针对固件当前输出的：

```text
$BE,<15 个字段>*XX\r\n
```

协议实现，不把 USB、驱动或 Web Serial/Python 串口读取返回的数据块误认为完整帧。

## 主要能力

- 使用 `pyserial` 枚举并连接本机串口，默认 `9600 8N1`、无流控。
- 严格以 `$BE,` 开始、以 `\r\n` 结束进行流式组帧。
- 对 `BE,...` payload 计算 XOR，并同时显示接收校验与本地计算校验。
- 将帧外字节单独标记为 `NOISE`，保留不会丢失信息的 HEX 表示。
- 同时显示驱动每次返回的 `RAW` 数据块，用来观察 USB/驱动如何拆分同一帧。
- 实时显示压力传感器、XDA 四合一电极、设备 Tick、主机接收时间和帧间隔。
- 保存最近的帧、噪声和原始块，可导出 JSON 与遥测帧 CSV。
- 内置演示模式：故意把一条帧拆成多个读取块，并周期性注入 Modbus 字节，验证查看器能够正确重组。
- 所有服务仅监听 `127.0.0.1`，默认不会暴露到局域网。

## 启动

项目不依赖系统全局 Python，使用 `uv` 自动安装 Python 和依赖：

```powershell
cd D:\Projects\stmcu-projects\blue-eye\tools\telemetry_viewer
uv sync --group dev
uv run python -m telemetry_viewer
```

启动后默认打开：

```text
http://127.0.0.1:8765
```

如果不希望自动打开浏览器：

```powershell
uv run python -m telemetry_viewer --no-browser
```

修改本地 HTTP 端口：

```powershell
uv run python -m telemetry_viewer --port 9000
```

## 接线

只接收 USART1 遥测时，建议先只连接两根线：

```text
STM32 PA9 / USART1_TX  →  CH340 RX
STM32 GND              →  CH340 GND
```

请使用 `3.3 V TTL` 电平。当前查看器不需要 CH340 TX，因此排查期间可以暂时不连接 `PA10 / USART1_RX`。

不要将普通 TTL 串口直接接到 RS485 的 A/B 差分端子。

## 页面使用

1. 点击串口旁的刷新按钮，选择 CH340 对应的 COM 口。
2. 保持 `9600`，点击“连接串口”。
3. 正常遥测帧会出现在“遥测帧历史”中。
4. 串口读取块会显示为蓝色 `RAW`。
5. `$BE,` 之前、帧之间或不完整数据会显示为黄色 `NOISE`。
6. 点击任意原始记录可以查看完整 ASCII escaped 和 HEX。
7. 设备帧间隔正常应接近 `5000 ms`。

如果还没有硬件，点击“演示模式”。演示数据周期为 1 秒，并模拟：

- 一帧被驱动拆为 11、21 和剩余字节三个读取块。
- 块之间存在 9 ms 和 24 ms 延迟。
- 每 5 帧注入一次 Modbus 请求和不可打印字节。

这些条件下，页面仍只应生成一条有效遥测帧，同时把 Modbus 字节单独标记为 `NOISE`。

## 遥测帧协议

### 完整帧结构

USART1 每次发送一行 ASCII 文本，语法为：

```text
$BE,<字段1>,<字段2>,...,<字段15>*XX\r\n
```

也可以写成更通用的形式：

```text
$<payload>*<checksum>\r\n
```

其中 `payload` 是 `BE,<15 个十进制整数字段>`，`checksum` 就是帧中显示为 `XX` 的校验值。

| 帧组成 | 字节数 | 线上内容 | 是否参与 XOR | 说明 |
|---|---:|---|:---:|---|
| 起始符 | 1 | `$`，ASCII `0x24` | 否 | 标记一帧开始 |
| Payload | 可变 | `BE,<15 个字段>` | **是** | 从字符 `B` 开始，到第 15 个字段的最后一个字符结束；逗号、数字和负号都参与校验 |
| 校验分隔符 | 1 | `*`，ASCII `0x2A` | 否 | 分隔 payload 与校验文本 |
| 校验字段 | 2 | `XX` | 否 | 两个十六进制 ASCII 字符，表示一个 8 位数值 `0x00`～`0xFF` |
| 行结束符 | 2 | `\r\n`，即 `0x0D 0x0A` | 否 | 标记一帧结束 |

`XX` 只是协议格式中的占位写法，并不是字面量，也不是第 16 个逗号字段。例如校验结果为十六进制 `0x38` 时，线上发送 `*38\r\n`；结果为 `0x05` 时必须保留前导零，发送 `*05\r\n`。

所有 15 个数据字段均使用 ASCII 十进制整数表示，不带单位、不含空格，也不使用十六进制形式。当前固件输出大写十六进制校验字符 `0`～`9`、`A`～`F`；查看器接收时也能解析小写 `a`～`f`，但新实现应按大写格式发送。

### `XX` 校验字段的计算方法

`XX` 使用初值为 `0x00` 的逐字节 8 位异或校验（XOR checksum）：

1. 取 `$` 后、`*` 前的原始 ASCII 字节，校验范围恰好是完整 payload。
2. 令 `checksum = 0x00`。
3. 按顺序执行 `checksum = checksum XOR 当前字节`。
4. 将最终 8 位结果格式化为两个大写十六进制字符，即 `XX`。

参与计算的是字符的 ASCII 字节，不是把 15 个字段先转换成数值再异或。例如字符 `B`、`E` 和 `,` 对应 `0x42`、`0x45` 和 `0x2C`；负数中的 `-` 对应 `0x2D`，同样参与计算。

下面这些内容不参与 XOR：

- 起始符 `$`；
- 校验分隔符 `*`；
- 校验字段 `XX` 自身；
- 结尾的 `\r\n`。

该 XOR 与 USART3 传感器总线使用的 Modbus CRC16 是两套完全不同的校验。`pressure_status=3` 或 `xda_status=3` 表示传感器 Modbus 响应的 CRC16 错误，不表示本条 `$BE,...*XX` 遥测帧的 XOR 错误。

等价的 Python 实现如下：

```python
def calculate_xor(payload: bytes) -> int:
    checksum = 0
    for byte in payload:
        checksum ^= byte
    return checksum


payload = b"BE,685220,0,2,0,0,0,-2147483648,0,0,0,2,0,0,0,0"
checksum = calculate_xor(payload)
frame = b"$" + payload + f"*{checksum:02X}\r\n".encode("ascii")

assert checksum == 0x38
assert frame == b"$BE,685220,0,2,0,0,0,-2147483648,0,0,0,2,0,0,0,0*38\r\n"
```

这个已知帧中：

```text
payload: BE,685220,0,2,0,0,0,-2147483648,0,0,0,2,0,0,0,0
XOR:     0x38
帧尾:    *38\r\n
帧尾HEX: 2A 33 38 0D 0A
```

注意帧尾 HEX 中的 `33 38` 是字符 `3`、`8` 的 ASCII 编码，并不是单个二进制字节 `0x38`。

接收端应先保存 `$` 与 `*` 之间未经修改的字节，再计算 XOR。不要在校验前删除负号、重新格式化数字、修改大小写或插入/删除空格，否则计算对象已经不再是发送端的原始 payload。

### 查看器如何判定一帧有效

查看器按以下顺序处理串口流：

1. 在任意串口读取分块中寻找 `$BE,` 起始标记；起始标记前的数据记为 `NOISE`。
2. 跨读取分块缓存数据，直到收到 `\r\n`，因此一次操作系统读取不要求刚好对应一帧。
3. 使用最后一个 `*` 分离 payload 和校验字段。
4. 要求校验字段恰好包含两个十六进制字符。
5. 对 `$` 与 `*` 之间的字节计算 XOR，并与收到的 `XX` 比较。
6. 要求 payload 标识为 `BE`，其后恰好有 15 个可解析为十进制整数的字段。

只有以上检查全部通过时，记录才标记为有效帧。XOR 不一致的帧不会被悄悄丢弃：查看器仍保留原始 ASCII、HEX、收到的校验值、本地计算值和错误原因，便于排查线路干扰或发送端实现问题。

### 15 个数据字段

| 序号 | 字段 | 固件数据类型 | 物理值/含义 | 有效性与注意事项 |
|---:|---|---|---|---|
| 1 | `tick_ms` | `uint32_t` | 构建本次统一快照时的 STM32 `HAL_GetTick()`，单位 ms | 这是快照时间，不是两个传感器各自的采样时间；约 `49.71` 天回绕一次 |
| 2 | `pressure_online` | `uint8_t` | 压力传感器在线标志：`0` 离线、`1` 在线 | 首次成功前为 `0`；成功后置 `1`；连续 3 次失败后置 `0`，所以一次失败时可能出现 `online=1` 且 `status!=OK` |
| 3 | `pressure_status` | 枚举 | 最近一次压力通信结果 | 状态码见下表；判断当前通信是否成功时应检查是否为 `1` |
| 4 | `pressure_read_mode` | 枚举 | `0` RAW、`1` FLOAT | 决定应使用字段 6/9 还是字段 5/7 解释压力值 |
| 5 | `pressure_float_valid` | `uint8_t` | FLOAT 压力有效标志：`0` 无效、`1` 有效 | RAW 模式固定为 `0`；FLOAT 模式成功读到有限浮点数后为 `1`，FLOAT 读取失败时重新变为 `0` |
| 6 | `pressure_raw` | `int16_t` | 压力寄存器 `0x0004` 的有符号原始值 | 仅在 RAW 模式下按 `pressure_raw / 10^pressure_decimal_point` 换算；FLOAT 模式下可能是之前保留的旧 RAW 值 |
| 7 | `pressure_value_x1000` | `int32_t` | FLOAT 压力值乘以 `1000` 后传输，接收端除以 `1000.0` 还原 | 仅当字段 5 为 `1` 时有效；否则固定发送 `-2147483648`（`INT32_MIN`）作为无效哨兵值；转换为整数时为 C 强制转换，截去超出小数点后三位的部分 |
| 8 | `pressure_unit_code` | `uint16_t` | 压力传感器寄存器 `0x0002` 的单位代码 | 当前固件接受 `0`～`23`；映射见下表 |
| 9 | `pressure_decimal_point` | `uint16_t` | RAW 模式的小数位数 | 当前固件接受 `0`～`4`；例如 `pressure_raw=1234`、该字段为 `2` 时，物理值为 `12.34`；FLOAT 模式下不要依赖该字段 |
| 10 | `xda_online` | `uint8_t` | XDA 四合一电极在线标志：`0` 离线、`1` 在线 | 规则与压力在线标志相同：首次成功后置 `1`，连续 3 次失败后置 `0` |
| 11 | `xda_status` | 枚举 | 最近一次 XDA 通信结果 | 状态码与压力状态相同 |
| 12 | `ec_x100` | `uint16_t` | EC 电导率寄存器值，实际值为 `ec_x100 / 100.0`，单位 mS/cm | 传感器通信失败时可能保留上一次成功值，应结合字段 10、11 判断 |
| 13 | `temperature_x10` | `int16_t` | 温度，实际值为 `temperature_x10 / 10.0`，单位 ℃ | 有符号值，可表示负温度；失败时可能保留上一次成功值 |
| 14 | `tds_ppm` | `uint16_t` | TDS，单位 ppm | 无额外缩放；失败时可能保留上一次成功值 |
| 15 | `salinity_ppm` | `uint16_t` | 盐度，单位 ppm | 无额外缩放；失败时可能保留上一次成功值 |

遥测帧没有传输压力与 XDA 的独立采样时间、样本序号和 Modbus 异常码。因此，`tick_ms` 只能表示快照生成时间；状态为 `MODBUS_EXCEPTION` 时，本帧也只能确认发生了 Modbus 异常，不能仅靠此帧确定具体异常码。

### 传感器状态码

`pressure_status` 和 `xda_status` 使用相同的数值定义：

| 数值 | 名称 | 含义 |
|---:|---|---|
| 0 | `IDLE` | 初始化后尚未完成一次通信，或当前没有可报告的结果 |
| 1 | `OK` | 最近一次请求成功，数据字段已更新 |
| 2 | `TIMEOUT` | 在规定超时时间内没有收到完整 Modbus 响应 |
| 3 | `CRC_ERROR` | 收到的 Modbus RTU 响应 CRC16 错误；与遥测帧尾 `XX` 的 XOR 无关 |
| 4 | `FRAME_ERROR` | Modbus 响应的地址、功能码、长度、字节数或数据范围等不符合预期 |
| 5 | `UART_ERROR` | STM32 UART/DMA 收发层报告错误 |
| 6 | `MODBUS_EXCEPTION` | 从机返回 Modbus 异常响应；具体异常码未包含在当前遥测帧中 |

`online` 与 `status` 表达不同信息：`status` 是最近一次通信结果，`online` 是带连续失败门限的在线判断。因此排障时应同时查看两者，不要把 `online=1` 直接等同于最近一次通信成功。

### 压力单位代码

`pressure_unit_code` 直接来自压力传感器寄存器 `0x0002`：

| 代码 | 单位 | 代码 | 单位 | 代码 | 单位 |
|---:|---|---:|---|---:|---|
| 0 | MPa | 8 | mmH2O | 16 | m |
| 1 | KPa | 9 | inH2O | 17 | cm |
| 2 | Pa | 10 | H2O | 18 | mm |
| 3 | Bar | 11 | mHg | 19 | Kg |
| 4 | MBar | 12 | mmHg | 20 | ℃ |
| 5 | kg/cm² | 13 | inHg | 21 | PH |
| 6 | psi | 14 | atm | 22 | ℉ |
| 7 | mh2o | 15 | Torr | 23 | 空/未指定 |

单位代码及压力寄存器的原始定义见 [RS485 压力变送器 Modbus-RTU 协议开发手册](../../docs/RS485%20压力变送器%20Modbus-RTU%20协议开发手册.md)，XDA 字段的量程和寄存器定义见 [XDA-10F-100P-7 四合一数字电极通信协议开发手册](../../docs/XDA-10F-100P-7%20四合一数字电极通信协议开发手册.md)。

## 常见问题

### 无法打开 COM 口

Windows 串口通常不能被两个程序同时独占。先在 BaudDance SerialAssistant 或其他串口助手中断开，再由本查看器连接。

### 能看到 RAW，不能看到 FRAME

检查 RAW/NOISE 的 HEX：

- 正常帧应以 `24 42 45 2C`，即 `$BE,` 开始。
- 正常帧应以 `2A XX XX 0D 0A` 结束。
- 如果出现 `02 03 ...` 或 `01 03 ...`，可能接到了 USART3 Modbus 总线。
- 如果一直是随机字节，检查共地、电平、引脚和是否有多个 TX 并联。

### 一帧仍显示多个 RAW

这是预期行为。RAW 表示操作系统/驱动每次返回的块；FRAME 才表示按照协议重组后的完整消息。
