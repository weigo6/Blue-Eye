# XDA-10F-100P-7 四合一数字电极通信协议开发手册

本手册专为开发者及AI代码生成模型设计，提取了 `XDA-10F-100P-7` 海水专用四合一数字电极（EC/温度/TDS/盐度）的核心通信协议规范，旨在指导 Modbus-RTU 驱动代码的编写与数据解析。

---

## 1. 通信基础配置

| 参数项           | 默认值 / 规格说明                                            |
| :--------------- | :----------------------------------------------------------- |
| **通信协议**     | 标准 Modbus-RTU                                              |
| **物理接口**     | RS485 (隔离型，隔离电源 1414VDC)                             |
| **默认从机地址** | `0x01` (范围 1~253)                                          |
| **默认波特率**   | `9600` bps                                                   |
| **数据格式**     | 8 数据位，1 停止位，无校验位 (**8N1**)                       |
| **广播地址**     | `0xFE` (用于未知地址时的查询或修改，此时总线上只能挂载一个该设备) |

## 2. 寄存器映射表 (Register Map)

所有寄存器均为 **16位 (1 Word)**。数据采用 **大端模式 (Big-Endian)**，即高字节在前，低字节在后。

### 2.1 数据寄存器 (只读)
| 寄存器地址 (Hex) | PLC地址 | 参数名称        | 数据类型       | 分辨率 / 转换公式                               | 量程范围           |
| :--------------: | :-----: | :-------------- | :------------- | :---------------------------------------------- | :----------------- |
|     `0x0000`     |  40001  | **EC (电导率)** | 16位无符号整型 | `实际值 = 寄存器值 × 0.01` (单位: mS/cm)        | 0～100 mS/cm       |
|     `0x0001`     |  40002  | **温度**        | 16位有符号整型 | `实际值 = 寄存器值 × 0.1` (单位: ℃，负数用补码) | 0～60 ℃ (支持负数) |
|     `0x0002`     |  40003  | **TDS**         | 16位无符号整型 | `实际值 = 寄存器值` (单位: ppm)                 | 0～50000 ppm       |
|     `0x0003`     |  40004  | **盐度**        | 16位无符号整型 | `实际值 = 寄存器值` (单位: ppm)                 | 0～65000 ppm       |

### 2.2 配置寄存器 (读/写)
| 寄存器地址 (Hex) | PLC地址 | 参数名称     | 写入值说明 (Hex / Dec)                                       |  缺省值  |
| :--------------: | :-----: | :----------- | :----------------------------------------------------------- | :------: |
|     `0x0030`     |  40049  | **设备地址** | `0x0001` ~ `0x00FD` (1 ~ 253)                                | `0x0001` |
|     `0x0031`     |  40050  | **波特率**   | `0x4800`(4800), `0x9600`(9600), `0x1920`(19200), `0x5760`(57600), `0x1152`(115200) | `0x9600` |
|     `0x0032`     |  40051  | **校验位**   | `0x0000`(无), `0x0001`(奇), `0x0002`(偶)                     | `0x0000` |
|     `0x0033`     |  40052  | **主动上报** | 单位: 秒。`0x0000`(关闭), `0x0002`(2秒上报一次)              | `0x0000` |
|     `0x007F`     |  40128  | **电极校准** | 写入 `0x0001` 触发一次校准动作                               | `0x0001` |

## 3. 数据解析算法 (Data Parsing)

在代码中读取到 16 位寄存器原始值（Raw Value）后，需按以下逻辑转换为物理量：

```python
# 伪代码示例
def parse_ec(raw_value):
    return raw_value * 0.01  # 单位: mS/cm

def parse_temperature(raw_value):
    # 处理有符号整数 (补码)
    if raw_value > 0x7FFF:
        raw_value -= 0x10000
    return raw_value * 0.1   # 单位: ℃

def parse_tds(raw_value):
    return raw_value         # 单位: ppm

def parse_salinity(raw_value):
    return raw_value         # 单位: ppm
```

## 4. 标准 Modbus-RTU 指令集 (Command Set)

以下指令均使用 **功能码 0x06 (写单个寄存器)** 或 **功能码 0x03 (读保持寄存器)**。
*注：报文中的 CRC16 校验码采用标准 Modbus CRC16 算法（多项式 0xA001），低字节在前，高字节在后。*

### 4.1 查询实时数据 (功能码 03)
读取地址 `0x0000` 开始的 4 个寄存器。
**请求 (主机 → 从机):**
|  地址  | 功能码 | 起始地址高 | 起始地址低 | 寄存器数量高 | 寄存器数量低 | CRC低  | CRC高  |
| :----: | :----: | :--------: | :--------: | :----------: | :----------: | :----: | :----: |
| `0x01` | `0x03` |   `0x00`   |   `0x00`   |    `0x00`    |    `0x04`    | `0x44` | `0x09` |

**响应 (从机 → 主机):**
|                             地址                             | 功能码 | 字节数 |   EC(H/L)   |  Temp(H/L)  |  TDS(H/L)   |  Salt(H/L)  | CRC低  | CRC高  |
| :----------------------------------------------------------: | :----: | :----: | :---------: | :---------: | :---------: | :---------: | :----: | :----: |
|                            `0x01`                            | `0x03` | `0x08` | `0x0D 0x80` | `0x00 0xFF` | `0x43 0x81` | `0x57 0xC2` | `0x3B` | `0x9F` |
| *(解析示例：EC=3456→34.56mS/cm, Temp=255→25.5℃, TDS=17281ppm, Salt=22466ppm)* |        |        |             |             |             |             |        |        |

### 4.2 修改设备地址 (功能码 06)
将设备地址修改为新地址（例如改为 `0x02`）。
**请求 (主机 → 从机):**
|                            原地址                            | 功能码 | 寄存器地址高 | 寄存器地址低 | 新地址高 | 新地址低 | CRC低  | CRC高  |
| :----------------------------------------------------------: | :----: | :----------: | :----------: | :------: | :------: | :----: | :----: |
|                            `0x01`                            | `0x06` |    `0x00`    |    `0x30`    |  `0x00`  |  `0x02`  | `0x08` | `0x04` |
| *(若忘记原地址，可将首字节替换为广播地址 `0xFE`，前提是总线上仅有一台该设备)* |        |              |              |          |          |        |        |

### 4.3 查询设备地址 (广播 0xFE)
使用广播地址读取 `0x0030` 寄存器以获取当前地址。
**请求 (主机 → 从机):**
| 广播地址 | 功能码 | 寄存器高 | 寄存器低 | 数量高 | 数量低 | CRC低  | CRC高  |
| :------: | :----: | :------: | :------: | :----: | :----: | :----: | :----: |
|  `0xFE`  | `0x03` |  `0x00`  |  `0x30`  | `0x00` | `0x01` | `0x90` | `0x0A` |

**响应 (从机 → 主机):**
|                广播地址                | 功能码 | 字节数 | 地址数据高 | 地址数据低 | CRC低  | CRC高  |
| :------------------------------------: | :----: | :----: | :--------: | :--------: | :----: | :----: |
|                 `0xFE`                 | `0x03` | `0x02` |   `0x00`   |   `0x02`   | `0x2D` | `0x91` |
| *(返回数据 `0x0002` 表示当前地址为 2)* |        |        |            |            |        |        |

### 4.4 修改波特率 (功能码 06)
将波特率设置为 `4800` (对应 Hex `0x4800`)。
**请求 (主机 → 从机):**
|  地址  | 功能码 | 寄存器高 | 寄存器低 | 波特率高 | 波特率低 | CRC低  | CRC高  |
| :----: | :----: | :------: | :------: | :------: | :------: | :----: | :----: |
| `0x01` | `0x06` |  `0x00`  |  `0x31`  |  `0x48`  |  `0x00`  | `0xEE` | `0x05` |

### 4.5 设置主动上报 (功能码 06)
设置每 `2` 秒主动上报一次数据。
**请求 (主机 → 从机):**
|               地址               | 功能码 | 寄存器高 | 寄存器低 | 时间高 | 时间低 | CRC低  | CRC高  |
| :------------------------------: | :----: | :------: | :------: | :----: | :----: | :----: | :----: |
|              `0x01`              | `0x06` |  `0x00`  |  `0x33`  | `0x00` | `0x02` | `0xF8` | `0x04` |
| *(写入 `0x0000` 则关闭主动上报)* |        |          |          |        |        |        |        |

### 4.6 触发电极校准 (功能码 06)
向 `0x007F` 寄存器写入 `0x0001` 触发校准。
**请求 (主机 → 从机):**
|  地址  | 功能码 | 寄存器高 | 寄存器低 | 数据高 | 数据低 | CRC低  | CRC高  |
| :----: | :----: | :------: | :------: | :----: | :----: | :----: | :----: |
| `0x01` | `0x06` |  `0x00`  |  `0x7F`  | `0x00` | `0x01` | `0x79` | `0xD2` |

## 5. 开发者注意事项 (Developer Notes)

1. **CRC16 校验计算**：
   - 必须使用标准的 Modbus CRC16 算法（多项式 `0xA001`，初始值 `0xFFFF`）。
   - 拼接 CRC 时，**低字节在前，高字节在后**（例如 CRC 计算结果为 `0x1234`，则报文末尾追加 `0x34 0x12`）。
2. **温度负数处理**：
   - 温度寄存器为 16 位有符号整数。在 C/C++ 中可直接强转为 `int16_t`；在 Python/Java 等语言中，若读取到的无符号值 `> 32767`，需减去 `65536` 以获取负数真值。
3. **响应超时与重试**：
   - 电极测量及内部计算需要时间，文档标明“稳定时间 < 15s”。在初次上电或校准后，建议代码层面增加适当的轮询间隔或超时重试机制。
4. **硬件安装与极化消除**：
   - 设备采用高频交流电测定法消除极化现象。代码层面无需干预，但需保证 RS485 线缆屏蔽层良好接地，以应对现场复杂干扰（设备内部已做多处隔离）。
5. **校准前置条件**：
   - 触发校准指令（`0x007F`）前，必须确保电极已在 12.85mS/cm 标液中静置 1 分钟以上且数据稳定，否则校准将产生严重偏差。
